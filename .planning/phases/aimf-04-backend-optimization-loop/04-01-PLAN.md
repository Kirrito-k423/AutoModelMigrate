<objective>
Define the reusable performance profile contract for Phase 4.

Purpose: make profiler-backed performance evidence explicit, comparable across GPU and NPU, and attachable to a migration manifest without collapsing backend-specific metrics into model logic.
Output: a human-readable performance profile spec, a JSON Schema, a MiniMax M3 example performance profile, and discoverability updates.
</objective>

<context>
Phase 4 starts only after correctness is green. The evidence model must satisfy D-04-01, D-04-02, and D-04-03 by capturing throughput, latency, memory, utilization, compile overhead, runtime stability, backend, dtype, hardware, sequence/context length, batch shape, and recipe/config identity in a shared top-level structure with backend-specific metric namespaces.

Use the existing seam from `docs/framework/adapter-contracts.md` and `docs/framework/backend-capability-matrix.md`: performance evidence belongs to `OptimizationLoop` and `BackendAdapter`, not to model semantics. Keep the Ascend NPU runtime blockers from `docs/ops/ascend-npu-runtime.md` visible as blocked evidence, not as a support claim.
</context>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-04-01-01 The schema overfits one profiler or backend and cannot compare GPU and NPU evidence side by side. | high | Use a common top-level contract with backend-specific metric namespaces and explicit backend, hardware, dtype, and workload fields. |
| T-04-01-02 Compile overhead or runtime stability is omitted because only throughput is visible in the first draft. | high | Make compile overhead and runtime stability required fields, not optional notes, and verify them in the example. |
| T-04-01-03 The MiniMax M3 example implies NPU execution support before root `npu-smi`, CANN, `torch_npu`, tensor smoke, and VeOmni smoke evidence exist. | high | Keep the example scoped to evidence capture, not support claims, and preserve blocked runtime fields for Ascend NPU. |
</threat_model>
