<objective>
Define the backend-specific optimization workflow for Phase 4.

Purpose: make profiler-backed tuning executable only after correctness remains green, keep GPU/NPU differences inside backend capability descriptors, and turn unresolved bottlenecks into backlog items with traceable ownership.
Output: an optimization-loop contract, a MiniMax M3 optimization report example, and lifecycle/capability/backlog updates that connect optimization evidence to backend maturity.
</objective>

<context>
Phase 4 optimization is downstream of Phase 3 correctness. The workflow must satisfy D-04-04 through D-04-11 by recording baseline, hypothesis, change, expected bottleneck, before/after metrics, correctness regression checks, acceptance results, rollback criteria, and backlog updates when a bottleneck remains unresolved.

Keep the `BackendAdapter` and capability-matrix boundary intact. GPU and NPU differences stay in capability rows and backend descriptors, not as scattered branches in model code. Ascend NPU performance work remains blocked until the runtime gates in `docs/ops/ascend-npu-runtime.md` are closed with root-approved `npu-smi`, CANN activation, matching PyTorch/PTA or `torch_npu`, tensor smoke, and the smallest VeOmni smoke.
</context>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-04-02-01 Optimization success is claimed from speed alone while correctness regresses or was never re-run. | high | Require a correctness regression check and a scoped acceptance result before any optimized status can be recorded. |
| T-04-02-02 Backend capability rows move to `optimized` without profiler output, before/after metrics, and rollback criteria. | high | Tie `optimized` maturity to linked performance profile evidence, the optimization report, and a regression guard. |
| T-04-02-03 The workflow converts a runtime blocker into a semantic failure or hides unresolved bottlenecks instead of routing them to backlog. | high | Keep runtime blockers separate from maturity, and require unresolved bottlenecks to produce owner-layer backlog items with evidence and first action. |
</threat_model>
